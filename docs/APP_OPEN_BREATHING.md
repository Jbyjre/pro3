# App-open breathing — 16 November 2026

The user opens original icons, notifications and links and asked for a 2–3-second pause. Breathe now uses **2.5 seconds**, with no in-app disable, snooze or Quick Settings toggle. This supersedes the November 15 shortcut-only design. The old camera island stays removed.

## Setup

Breathe → Choose apps → Connect Breathe → allow **pro · Breathe** in Android Accessibility. The page distinguishes missing access, enabled-but-not-connected and ready. It refreshes when returning from Settings, offers the app-specific accessibility details route with a general Settings fallback, and provides App info for Android's restricted-settings recovery. No Bluetooth, usage access, Display over other apps or notification permission is needed by this service.

## Trigger and timing

`BreathAccessService` subscribes only to `TYPE_WINDOW_STATE_CHANGED`, with `notificationTimeout=0` and `canRetrieveWindowContent=false`. Selected packages' activity classes, labels, saved appearance and native view are prepared before entry. A known selected activity attaches the layer synchronously in the event callback: no handler debounce, package/icon scan, backend, Bluetooth call, network request or animation wait. Unknown activity classes are validated on IO; dialogs, keyboards and content-change events cannot create a new pause. Out-of-order query results cannot override a newer confirmed transition.

The opaque, touchable `TYPE_ACCESSIBILITY_OVERLAY` covers the app area while system navigation remains available. It never launches/replaces the underlying activity, preserving notification/deep-link destinations. A monotonic first-draw deadline removes it at 2,500 ms; visual animation scale does not control the deadline. The existing native color/type renderer is shared by the preview and compatible legacy shortcuts. Repeated events within a package do not restart the clock. A different selected package replaces the current layer. Home/Back, screen off, system UI, permission loss and service destruction clean up the window and pending deadline. Routine headphone pop-ups are suppressed through the existing shared ownership gate.

The service has no usage polling, resident foreground-service notification, wake lock, screen-tree/text read or automatic app relaunch. Android manages its binding. Preferences survive process replacement; revoked access, force-stop, uninstall and system-managed shutdown remain under Android's control. Setup reports the enabled flag separately from the live connection. No app can truthfully promise that this permission is irrevocable.

## Coverage and limits

Normal icons, notification destinations, links and Recents use the same event-driven transition path when entering a chosen package. A second activity within an already foreground package does not add another pause. Original launch intents are untouched. Keyboard/dialog/system windows are not considered app entries. Existing pinned shortcuts still pause before launching and exempt that immediate handoff from a duplicate service layer.

Accessibility events describe window changes after Android has begun opening a destination. This is the earliest event-driven ordinary-icon route used here, not a pre-launch veto. An initial destination frame may still be visible. Neither subsecond Samsung latency, absolutely zero target exposure, nor background survival on every OEM is certified by cloud tests. `Breathe` logs attach-to-first-draw milliseconds for device investigation; this excludes OS event-delivery latency. Device acceptance checks are in [TESTING](../TESTING.md).

The app-specific Settings intent/flattened component format was checked against [AOSP AccessibilityDetailsSettingsFragment](https://github.com/aosp-mirror/platform_packages_apps_settings/blob/master/src/com/android/settings/accessibility/AccessibilityDetailsSettingsFragment.java). The action is not a public SDK constant, so the code uses its platform action string and falls back to public accessibility settings if unavailable.

## Smoother, once-per-visit pause — 18 November

Jake asked for a pause that lays over the app instantly while it keeps loading, never flickers or cuts off, breathes once per visit (not on every app switch), runs 3 seconds, is customizable, ignores Chrome web apps, and is actually useful to breathe with. Everything below was found by reading this code and Android's/Chromium's own sources, not guessed.

### Why it felt delayed, cut off and flickery
1. **System windows cancelled a running pause.** Any window event from Android's system UI (a heads-up notification, the volume panel) or the permission controller hid the layer. That ended it halfway, at random. A running pause now ignores them; Home, Back, screen off, another app taking over, losing the chosen app or losing the permission still end it.
2. **A hard cut at the end.** The layer vanished from solid color straight to the app. It now fades or lifts away, finishing exactly when the run ends.
3. **Strips of the loading app.** The window was inset to leave the status bar and navigation area uncovered, so the app flickered above and below the color. It now covers the whole screen. Only the parts Android calls *tappable* (three-button navigation's buttons) are left out, so those stay usable. Rotation or folding during a pause re-fits it.
4. **A color change at the start.** It began in a near-black unrelated to the gradient, then the colored sheet rose. It now begins as a dark tint of the chosen gradient's own color (blend toward black, which stays in the displayable range; a first attempt in Lab color shifted Tangerine toward red and was caught by a test).
5. **Mid-animation rebuilds.** A settings reload could replace the gradient while it animated, and the pause history would have triggered that reload. Identical options are now ignored, and history is kept in its own file (`breath_seen`).
6. **Timing.** Motion follows Android's own frame timestamp (`View.drawingTime`), so a dropped frame cannot change how long it lasts. The deadline still uses the monotonic clock, as before.

**Ruled out:** software drawing. AOSP's `WindowManagerGlobal.addView` sets the hardware-acceleration flag for windows without a parent from the app's manifest setting, and pro's manifest does not disable it (checked in the source on 18 November). It is not claimed as a cause.

**Cannot be removed from the cloud:** Android tells the service an app opened from `ViewRootImpl.performTraversals`, after the app has laid out its window and just before its first draw. The layer can only be made as fast as possible after that event, so a brief glimpse of the app's first frame may remain. The Breathe page now shows the last pause's measured speed ("the layer was attached N ms after Android reported the app, and drew M ms after that") so this can be measured on the phone instead of guessed. Cold-start splash windows are not used as triggers: their accessibility events were not verified, and a wrong guess could pause floating bubbles or overlays.

### Once per visit, with no battery cost
`BreathAppGate` remembers when each chosen app last paused. An app pauses on first open, then stays quiet while you move between apps you already opened, and pauses once more when it is opened after the grace time (default **10 minutes**, choices Every open / 5 min / 10 min / 30 min / 1 hour). The time is measured from when that app's last pause *started* and is compared only when a window opens: no timer, no polling, no wake-ups. A pause counts only once its first frame is drawn, so a layer that failed to show never uses up an app's turn. Leaving to Home during a pause still counts. Locking and unlocking inside the grace time does not pause again. History survives service and process restarts (`breath_seen`, entries older than 24 hours are dropped). A clock set backwards counts as long ago, never as never again.

Reading of the request: "if it's still open for more than 10 minutes, run it again" is applied as *on the next open after 10 minutes*, not as an interruption in the middle of using an app. A mid-use re-pause would be intrusive and would need a timer, which the battery requirement rules out.

### Chrome web apps
Verified against Chromium's current sources (`components/webapps/docs/identifiers.md`, `android_architecture.md` and `chrome/android/java/AndroidManifest.xml`, read 18 November): a web app installed from Chrome is its own package `org.chromium.webapk.<hash>` (or `com.android.webapp.<hash>`), but its window runs inside the browser's package as `org.chromium.chrome.browser.webapps.WebappActivity` or `SameTaskWebApkActivity`, so Android reports it as **Chrome**. `BreathWebApps` therefore skips both the packages and those windows, even when Chrome is a chosen app, clears any pause that began for the browser, and treats coming back to Chrome itself as a new entry. Installed web apps are hidden from Choose apps and can never be saved as a chosen app. A plain "Add to Home screen" page shortcut opens an ordinary Chrome tab and cannot be told apart, so it pauses. Not verified on a phone.

### Length, transitions, words (all customizable)
Length 2–10 s (default **3 s**) is the whole run, from the layer covering the app to the app fully visible. The shape scales with it: the first half is the inhale (the gradient rises through the dark base), the second half the exhale (words change, then the layer clears). Transition: **Fade** (default), **Lift** (a curtain with a curved, light-edged bottom rises away) or **Instant**. Words: **Mix** (steps through the three sayings), or a fixed one. Sayings, each a pair for in and out: *Breathe in / Breathe out*, *Slow down / No rush*, *Reset / Ready*, each with a small line ("Slow, through your nose", "Still want this?", "Your call"). Type is **Barlow Condensed** ExtraBold and SemiBold (SIL Open Font License, bundled with its license), upper-case, tight. The app name at the bottom left is **off by default** (the request read "take out … that doesn't really need to be there"); a "Show app name" switch brings it back.

### Making it worth the wait
Guided words that change as you breathe in and out; a thin line that shortens so you can see how long is left; a soft light that follows your finger; gentle haptics (a soft tick as the words change and one near the end, using Android's `CLOCK_TICK` and `CONFIRM`, off with one switch, and respecting the phone's touch-feedback setting); a light-catching edge on the rising color. Evidence for slow breathing is positive but modest. In [a 2021 randomized trial in Frontiers in Psychology](https://www.frontiersin.org/articles/10.3389/fpsyg.2021.624254/pdf) (96 people), those trying to breathe at 6 breaths a minute showed higher heart-rate variability even though they averaged about 12 a minute; other trials report lower anxiety scores. Results on in/out ratios are mixed, so none is claimed: the exhale is simply as long as the inhale. (I read search summaries of these studies, not the full papers.)

Installing is still only started by the idle job or a deliberate tap. The scheduled job carries a version stamp so changed rules replace an older waiting job once. Phone → App updates shows "Last checked …".

## The pause rule, verse, colors, exits and updates — 19 November

Jake reported that Breathe still felt spotty (it worked for one app and not another), clarified exactly when it should pause, asked for the Psalm 51:10 reference as the only words, random and selectable colors, more smooth exits, grayscale readiness, and a reliable update on his Galaxy S26 FE even with Auto Blocker.

### When it pauses (and what Android cannot tell us)
Jake's rule: switching back to an app through Recents or a swipe must **not** pause; closing an app and opening it again **must**. Two facts, both read in Android's own source on 19 November 2026, mean a service that does not read the screen cannot know "closed" for certain:
- The usage log hides the event for a destroyed screen. `UserUsageStatsService` calls `ACTIVITY_DESTROYED` "a private event" that is dropped or converted to "stopped".
- A brand-new screen gets a new window id, which would settle it, but `AbstractAccessibilityServiceConnection` removes the source (including the window id) from every event sent to a service without content access (`event.setSource((View) null)`).
Jake was asked and chose to **keep screen-content access off**. So `BreathAppGate` uses what it can see: what was in front just before, whether another app was in front since this app left, how long it was away, and when it last paused.
- **New opens** (default): pauses on the first open; when you come from Home or Recents after at least 2.5 seconds with no other app in between (closing and reopening looks exactly like this); or from a notification (the shade, or a heads-up, appeared within 4 seconds). Going through another app and back does not pause. Coming back from Home or Recents faster than 2.5 seconds is a peek.
- **Every time**: pauses every time the app comes forward. **After a break**: first open, then only after the break time. All three can be set per app (Choose apps → the gear), with a per-app length up to 30 seconds. "Pause again after" (Never / 5 min / 10 min / 30 min / 1 hour) applies on top: after that long since its last pause even a simple switch-back pauses.
- The one case it cannot catch: closing an app, opening a *different* app, then going back to the first (Android's event stream for that is identical to switching through Recents). This is documented in the app under How Breathe works.
- Launcher and Recents are recognised by the Home app (`queryIntentActivities` for the HOME intent) and by SystemUI windows whose class names contain "recent" or "shade/notification". Samsung's real class names are **not verified**; the "Recent decisions" list shows them so they can be confirmed on the phone.

### Why it seemed spotty, and what was hardened
- **The earlier 10-minute rule was the wrong model.** After closing and reopening an app inside 10 minutes nothing happened, which looked like a random failure. Replaced by the rule above.
- Unlock and screen-off no longer lose an entry: an app opened from the lock screen or while the screen is off keeps its turn and pauses when the phone is on and unlocked; waking into the same app is judged by how long the screen was off. The screen turning off no longer forgets which app is in front.
- Only the Home launcher gets a 0.7-second grace after a layer appears (launchers report stray windows while an app opens). Any other app taking over ends the pause at once, and a different chosen app's pause replaces the old one.
- **Recent decisions** (Breathe page) lists, in plain words, every choice: "pausing: opened from Home or Recents", "no pause: switched back through another app", "ignored a window that is not a screen of the app", "waiting for unlock", with a Copy button. It is kept in memory only and holds app names and window names, never screen text.

## Smoother, more reliable Breathe, case-open card, voice-typing stability, and smarter audio — 20 November

### Why Breathe sometimes missed an open or felt delayed
1. **A late launcher window event during the 700 ms opening grace overwrote the gate's front app.** When an app opened from Home, line 295 ignored `hide()` during the first 700 ms (`PROTECT_MS`), **but line 291 still called `BreathAccess.gate.enter(pkg, Kind.Launcher)`**. Whenever the launcher reported a late window event while the chosen app was opening, `gate.foreground` was overwritten with the launcher; if the opening app then transitioned from its splash screen to its main screen, or when the user later left and came back, the gate's state was wrong. Fixed: launcher events arriving while `attached && mono < protectUntil` now return immediately before touching `BreathAccess.gate`.
2. **Samsung One UI launcher companions and transient system windows.** Opening an app from Samsung Finder (`com.samsung.android.app.galaxyfinder`) or Edge Panels (`com.samsung.android.app.cocktailbarservice`, `com.samsung.android.app.appsedge`, `com.samsung.android.app.taskedge`) was classified as `Window.App` instead of `Window.Launcher`, marking `sawApp = true` and skipping the pause as `"switched back through another app"`. Likewise, transient system overlays (share sheet `intentresolver`, biometric prompt, App Lock, keyboards, Smart Capture, Game Tools) could be treated as `Window.App`. Finder and Edge Panels now count as `Window.Launcher`, and transient system overlays count as `Window.Ignore`.
3. **Zero-delay classification for every installed app.** Previously `refresh()` only preloaded activity classes for the *chosen* apps, so switching to an unselected app triggered an async `Dispatchers.IO` `getActivityInfo` lookup before the gate learned that you switched away. `refresh()` now also preloads all `CATEGORY_LAUNCHER` activities across the phone so ordinary app switches are classified synchronously (0 ms) on the main thread.
4. **Natural Home-to-app reopen timing (`1.2 s`).** `BreathAppGate.HOME_GAP_MS` was `2,500 ms` (2.5 s), which rejected closing an app to Home and reopening it in 1.2–2.4 seconds as `"back from Home or Recents within a moment"`. Lowered to `1,200 ms` so any deliberate 1.2 s+ reopen from Home or Recents pauses, while sub-second glances stay quiet.
5. **Pre-warmed shaders/layout and sleeping the frame clock.** `BreathAccessService.refresh()` now pre-warms `BreathView.prewarm(width, height)` so the first drawn frame does zero shader allocation or text measurement. Steady notes (`inNote == outNote`) stay still across the midpoint instead of fading out and back in, and `BreathView.schedule` sleeps via `postInvalidateDelayed` whenever a steady phrase is settled (both in Still mode and during the 0.50–0.52 midpoint hold), saving display and GPU wake-ups.

### AirPods case-open card & notification, voice-typing disconnect fix, and smarter auto-pause / auto-play
