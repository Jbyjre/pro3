# Services and active rules

Current behavior supersedes the historical camera-island notes: [breathing and updates](../../../../../../../../../docs/BREATHING_AND_UPDATES.md).

| Area | Source and lifetime |
|---|---|
| Headphone control | AirPodsService, AACPManager, HeadphoneLink, DeviceChoice, SmartAudioRules; existing connectedDevice foreground service and bounded reconnect work. AirPods/Beats controls and normal Bluetooth-on use are preserved. SmartAudioRules prevents false ownership yields and redundant A2DP reconnects on non-rooted Android phones or during HFP/SCO voice typing, suppresses Conversation Awareness ducking while recording/in a call, persists ear-detection auto-pause so putting AirPods in after 15+ minutes or hours brings music right back (with BLE ear-detection head start, direct MediaSession wake + media key + 380 ms follow-up nudge), wakes the case-open card/notification on BLE or AACP case transitions, and alerts via IslandEvent.Problem and the status notification if the link drops unexpectedly while worn or active. |
| Temporary events | IslandPrefs retains master/duration/haptics/song names and headphone triggers; show_bottom_sheet_popup ("Card when the case opens") is on by default and exposed on the Phone tab. AirPodsService and HeadphoneLink supply connection/music/battery/disconnect events to GlintOverlays; no permanent camera window. |
| Music | NowPlaying uses media-session callbacks with optional Notification access and media-key fallback. Metadata updates reuse the selected session, buffering counts as active, cover art stays with its source app, and duplicate icon loads are coalesced off main. MediaAccessService does not read or attribute other notifications. SoundSource is only a bounded real-app name/icon cache, with no playback or screen listeners. MusicPulse is acquired/released by visible music pop-ups. |
| Heart | HeartRate, HeartView, HeartPacing, HeartHistory/Backup/Link, HeartLocal (phone-only link to the JWR workout app), CommandFeedback; existing Smart pacing and screen-off/battery behavior remain. |
| Phone | PhoneStatus/PhoneControls battery and torch observation is owned by the visible Phone page and detached when paused/disposed. IslandTimer/TimerReceiver restores the elapsed deadline on the same boot and uses the saved wall deadline after a reboot. Phone shows a foreground-only countdown with pause, resume, extend and cancel controls. |
| Breathing | ../breathing: BreathAccessService owns a prepared accessibility overlay for selected app-window transitions, with a 3-second default first-draw deadline. No screen-content access, polling, Bluetooth dependency or foreground service. BreathActivity keeps old shortcuts compatible; shared ownership prevents duplicate pauses. |
| Updates | ../updates: sparse persisted JobScheduler work, bounded HTTP/downloads, APK signature validation, PackageInstaller sessions/results. Optional idle install uses platform constraints on API 34+. |
| Migration | FeatureMigration deletes camera-only keys once and enables the case-open card default once, preserving unrelated preferences. No whole-settings reset. |
| Efficiency | PowerPlan, GlassBudget, WhileShown, FrameRate, BLEManager scanning policies (immediate reportDelay=0 delivery with AirPods Pro 3 BLE IDs and close-range unverified fallback), VolumeGuard, BatteryEstimator and existing recovery work remain. No measured battery-saving percentages are claimed. |

Removed: MiniIslandRules, IslandLook, camera gestures/editor, IslandAccessService, screen observation/reading/voice, live-notification glance, audio/source attribution and related popup suppression. Their dedicated tests were retired with the feature; mixed popup/phone/heart/battery coverage was retained and updated. Never reintroduce these through a hidden setting.

No sockets, package scans, icon decoding, files, network or root waits on main. Keep background work owned and cancellable. Test service/model behavior and true failure paths rather than merely mirroring implementation.
