# Check app-open breathing on the phone — 16 November

1. Install the new **correctly signed** build over pro; keep existing data. Open Breathe. Choose an ordinary app, tap Connect Breathe and enable **pro · Breathe** in Android Accessibility. If restricted, use the App info link and Android's Allow restricted settings. Return: it must say **Ready when you open** only when Android has enabled and connected the service. No shortcut, Bluetooth, overlay permission, usage access or notification access is needed for breathing.
2. Open a selected app with its **original icon**, then via a notification, a web/deep link from another app and Recents. Measure event/open-to-first-layer separately from the **2.5 seconds from the first breathing frame**. Record a screen video; the Android event can arrive after the destination's first frame, so cloud tests cannot certify zero exposure or subsecond Samsung latency. Logcat tag `Breathe` records attach-to-first-draw time without package names or screen content.
3. Confirm the exact conversation/article opened by a notification/link remains after the pause; no launch of the app's home activity. Try app-internal activity switches, dialogs, keyboards, rapid A→B→A and Home→same-app reentry. One layer only; duplicate events never extend it.
4. During the pause use Home, Back (button and gesture), lock, notification shade and incoming calls. No stuck touch target, delayed app launch or replay. Try rotation, split screen and display-size changes. Accessibility window ordering and gestures require real-device validation.
5. Try Cobalt/Tangerine/Pool, Still mode, system animation scales 0×/1×/10× and 1.8× text. Preview and live layer should match; duration stays 2.5 seconds. Breathe has no off/pause/tile control. Old disabled/snoozed preferences must not bypass it. Removing an app from the chosen list removes coverage for that app.
6. Close pro's task, restart the phone, revoke/regrant access, force-stop and reopen pro, then upgrade. Confirm selections survive and connection status is accurate. Android can stop/revoke access; the app must never claim connected when it isn't. A force-stop is not something pro can bypass.
7. Recheck AirPods/Beats listening controls, music, heart readings and temporary pop-ups. Routine headphone events should not cover or extend the breath. Keep original app identity/signature and existing update flow. Follow the updater and headphone checks in [the previous checklist](docs/BREATHING_AND_UPDATES.md).

Cloud unit/integration/render tests are recorded in [the delivery notes](docs/APP_OPEN_BREATHING.md). They do not measure a physical Galaxy's event delivery, compositor timing, gesture behavior, background retention or Bluetooth.
